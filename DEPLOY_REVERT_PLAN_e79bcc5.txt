Your current local changes (what we may need to revert)
---------------------------------------------------------
These local changes are the ones that may affect trade quality:

A) watcher.py: hard rejection for SL distance > 2.0 x ATR
   - (instead of old behavior: warning only for > 6.0 x ATR)

B) watcher.py: wick-based buffer for wide-range Range Breakout suggested_sl
   - (instead of old behavior: suggested_sl = boundary +/- buf)

C) services/llm_service.py: prompt text changed from 1.0–6.0 to 1.0–2.0
   - (aligns with A/B; affects LLM output)

Bug-fix changes you likely want to KEEP (do not revert unless you choose full revert)

1) watcher.py: auto-range "first breakout" handling
   - When auto-range is in the 'first breakout' state, it should set
     range_breakout_wait_confirmation and preserve the range snapshot for the next cycle.
   - This prevents the "lost confirmation" scenario like your 4875-4860 example.

2) watcher.py: is_entry_filled() guard
   - If entry_notified=True (or entry_notified_at exists), then is_entry_filled() returns True.
   - This prevents the manager from cancelling as "Entry not reached" after the monitor already
     broadcasted "entry reached".

3) watcher.py: validate_llm_verdict_strict — правильная сторона SL/TP относительно входа (KEEP)
   - После корректировки entry на current_price проверяется геометрия сделки:
     * BUY: SL строго НИЖЕ входа, TP строго ВЫШЕ входа; иначе → WAIT.
     * SELL: SL строго ВЫШЕ входа, TP строго НИЖЕ входа; иначе → WAIT.
   - Зачем: LLM иногда выдаёт «перевёрнутый» стоп (напр. SELL со SL ниже входа). Тогда Price Monitor
     считает SL hit по условию price >= stop_loss сразу после входа — ложное закрытие и бессмысленный PnL.
   - Этот фикс НЕ относится к спорным лимитам 2.0×ATR vs 6.0×ATR (пункты A/B/C выше).
     При откате SL-математики к 6.6 — логику направления SL/TP лучше ОСТАВИТЬ (не откатывать).
